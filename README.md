# Визуализатор графа зависимостей

## Общее описание

Консольный инструмент на Go для визуализации графа зависимостей
пакета в формате Alpine Linux (apk). Менеджеры пакетов и
библиотеки для получения информации о зависимостях не
используются: индекс репозитория скачивается и разбирается
стандартными средствами языка (`net/http`, `compress/gzip`,
`archive/tar`). Единственная внешняя библиотека —
`github.com/BurntSushi/toml` для чтения конфигурации.

Этапы разработки:

1. Конфигурация: чтение и проверка параметров из TOML.
2. Сбор данных: получение прямых зависимостей пакета заданной
   версии по URL репозитория Alpine (текущий этап).

## Структура проекта

* `src/main.go` — точка входа, разбор командной строки, коды возврата;
* `src/collect.go` — выбор источника индекса и поиск пакета;
* `src/output.go` — вывод прямых зависимостей;
* `src/config/` — чтение и проверка конфигурации TOML;
* `src/apk/dependency.go` — разбор записи зависимости;
* `src/apk/index.go` — разбор файла `APKINDEX`, поиск пакета;
* `src/apk/source.go` — загрузка индекса по URL и из файла,
  распаковка `APKINDEX.tar.gz`;
* `tests/` — тестовый репозиторий, конфигурации и скрипты `.sh`;
* `config.toml` — конфигурация по умолчанию (тестовый репозиторий);
* `run.sh` — запуск в Linux.

## Параметры конфигурации

Все параметры обязательны.

| Ключ | Тип | Описание | Проверка |
|------|-----|----------|----------|
| `package_name` | строка | имя пакета (поле `P:` индекса) | не пустое, до 214 символов, допустимы буквы, цифры и символы `@ . _ / : + -` |
| `repository` | строка | URL репозитория или путь к файлу индекса | зависит от `repository_mode` |
| `repository_mode` | строка | режим работы с репозиторием | `"remote"` или `"test"` |
| `version` | строка | версия пакета (поле `V:`), например `8.5.0-r0` | не пустая, до 128 символов, формат вида `1.3.0`, `2.0.0-beta.1`, `1.2.4_git20230717-r4` |
| `ascii_tree` | bool | вывод в виде ASCII-дерева (на следующих этапах) | `true` или `false` |
| `max_depth` | целое | максимальная глубина анализа (на следующих этапах) | от 1 до 100 |

### Режим `remote`

`repository` — URL каталога репозитория Alpine с архитектурой:

```text
https://dl-cdn.alpinelinux.org/alpine/v3.19/main/x86_64
```

К нему добавляется `/APKINDEX.tar.gz`. Можно указать и полный
URL файла, оканчивающийся на `.tar.gz`. Допустимы схемы `http` и
`https`.

### Режим `test`

`repository` — путь к существующему локальному файлу индекса
(относительные пути считаются от текущего каталога). Файл — это
текстовый `APKINDEX`: записи через пустую строку, поля вида
`P:имя`, `V:версия`, `D:зависимости`. Архивы в репозиторий не
добавляются; если указать скачанный `APKINDEX.tar.gz`, он тоже
будет прочитан.

Пример `config.toml`:

```toml
package_name = "curl"
repository = "tests/test_repo.txt"
repository_mode = "test"
version = "8.5.0-r0"
ascii_tree = true
max_depth = 3
```

## Как устроено получение зависимостей

1. Индекс загружается по HTTP (или читается из файла). Архив
   состоит из двух склеенных gzip-потоков: подписи и самого
   индекса, поэтому он читается как один непрерывный tar.
2. Из архива берётся файл `APKINDEX`. Для обычного текста
   распаковка не нужна: формат определяется по первым байтам.
3. Записи разбираются по полям: `P:` — имя, `V:` — версия,
   `D:` — зависимости через пробел.
4. Ищется запись с заданным именем и точно совпадающей версией.
5. Зависимость имеет вид `имя`, `имя>=версия`, `so:libc.musl-x86_64.so.1`,
   `cmd:sh`, `pc:openssl~3.1`. Поддерживаются операторы `<`, `>`,
   `=`, `~` и их сочетания. Записи с префиксом `!` — это
   конфликты, а не зависимости, поэтому в результат они не входят.

Зависимости выводятся так, как записаны в индексе. Виртуальные
(`so:`, `cmd:`, `pc:`) не заменяются именами пакетов.

## Запуск

Перед первым запуском нужно скачать библиотеку TOML и создать
`go.sum`:

```sh
go mod tidy
```

Запуск (при необходимости сначала `chmod +x run.sh tests/*.sh`):

```sh
./run.sh
go run ./src --config config.toml
go run ./src -h
```

Без параметра `--config` используется `config.toml` в текущем
каталоге.

Пример вывода:

```text
Package: curl 8.5.0-r0
Direct dependencies (4):
  ca-certificates
  so:libc.musl-x86_64.so.1
  so:libcares.so.2
  so:libcurl.so.4
```

Если зависимостей нет: `Direct dependencies: none`.

### Работа с реальным репозиторием

1. Запустите `go run ./src --config tests/remote_wrong_version.toml`.
   Версия `0.0.0-r0` не существует, и программа покажет реальные:
   `version 0.0.0-r0 of package busybox not found, available: ...`.
2. Подставьте найденную версию в `version` своего файла
   конфигурации с `repository_mode = "remote"` и запустите снова.

## Обработка ошибок

Ошибки конфигурации (этап 1) показываются списком, все сразу:

```text
error: invalid configuration:
  - package_name: contains invalid characters: "bad name!"
  - repository: URL scheme must be http or https, got "ftp"
  - version: invalid version format: "v 1.0"
  - max_depth: must be at least 1, got 0
```

Ошибки получения данных:

```text
error: package not found: no-such-package
error: version 1.0.0-r0 of package curl not found, available: 8.5.0-r0, 8.4.0-r0
error: cannot download https://.../no_such_arch/APKINDEX.tar.gz: server answered 404 Not Found
error: cannot download http://127.0.0.1:9/.../APKINDEX.tar.gz: Get "...": dial tcp ...: connection refused
error: invalid index https://.../APKINDEX.tar.gz: invalid gzip data: ...
error: invalid index https://.../APKINDEX.tar.gz: archive has no APKINDEX file
```

Коды завершения:

| Код | Значение |
|-----|----------|
| `0` | успех |
| `1` | ошибка конфигурации |
| `2` | неверные аргументы командной строки |
| `3` | ошибка получения данных |

## Тестирование

Модульные тесты (включая загрузку по HTTP через `httptest`, а также
разбор архива с сигнатурным сегментом, повреждённого архива и архива
без `APKINDEX`; архивы создаются в памяти, файлов-архивов нет):

```sh
go test ./...
```

Сценарии демонстрации (запускаются из любого каталога):

| Сценарий | Что показывает |
|----------|----------------|
| `tests/test_local.sh` | пакет с зависимостями, ограничения версий, пакет без зависимостей, конфликты |
| `tests/test_data_errors.sh` | пакет не найден, версия не найдена |
| `tests/test_remote.sh` | реальный репозиторий Alpine (нужен интернет): неверная версия, неверный URL, недоступный сервер |
| `tests/test_config_errors.sh` | ошибки всех параметров конфигурации, файла и аргументов |

Тестовый репозиторий `tests/test_repo.txt` содержит пакеты `curl`
(две версии), `openssl`, `musl`, `demo-conflicts`.
